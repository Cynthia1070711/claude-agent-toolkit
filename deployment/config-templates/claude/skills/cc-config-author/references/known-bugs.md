## #23478 — paths 規則在 Write 工具觸發時不載入

**Status**:Open(2026 Feb 5 開立)
**確認平台**:macOS,Windows 推測同
**嚴重度**:🔴 高(影響「檔案創建時規則」整類功能)

### 症狀

```yaml
# .claude/rules/markdown.md
---
paths: ["**/*.md"]
---
# 創建新 .md 檔案時要加 "# Created on YYYY-MM-DD" 標頭
```

```
User: "Create file foo.md with content 'hello'"
Claude: [creates foo.md with just "hello", ignoring the rule]
```

**原因**:`paths:` 在 Read 工具觸發時載入,**Write 工具不載入**。Claude 寫入新檔案時不會看到對應規則。

### Workaround

#### 方案 A — 規則同時放 CLAUDE.md(犧牲細粒度)

```markdown
# CLAUDE.md
## File creation conventions
- 新建 .md 加 `# Created on YYYY-MM-DD` 標頭
- 新建 .ts 加 license header
```

代價:always-on tokens 增加。

#### 方案 B — PostToolUse hook 兜底

```json
{
  "PostToolUse": [{
    "matcher": "Write",
    "hooks": [{
      "type": "command",
      "command": "node .claude/hooks/post-write-rules-loader.js"
    }]
  }]
}
```

Hook 偵測新建檔案類型,注入 `additionalContext` 告知 Claude 「請 Read 此檔並依據對應 rule 修正」。代價:3 步操作(Write → Read → Edit)變成 1 步該做的事。

#### 方案 C — 規則寫在 SKILL.md 並有具體 trigger

把規則改寫成 skill,description 包含「新建 X 檔時 use this skill」。代價:依賴 description matching 準確度。

### 連結

https://github.com/anthropics/claude-code/issues/23478

## #21858 — user-level rules 的 paths frontmatter 完全失效

**Status**:Open(2026 Jan 30)
**確認平台**:Windows(macOS 未測但推測同)
**嚴重度**:🔴 高(跨專案 paths 規則整類失效)

### 症狀

```yaml
# ~/.claude/rules/csharp.md
---
paths: ["**/*.cs"]
---
# C# 程式碼規範
- 使用 PascalCase
- async 方法加 Async 後綴
```

```
User: 編輯任何 .cs 檔
Claude: 規則完全不載入,Claude 不知道有這條規則
```

`/memory` 列出的清單也**不會**列出此規則。

### Workaround

#### 方案 A(推薦):規則放專案層

把規則移到專案層 `.claude/rules/csharp.md`,paths 在那邊有效(注意 Bug #23478)。

#### 方案 B:多專案 symlink 同一份規則

```powershell
# 在每個 C# 專案執行
New-Item -ItemType SymbolicLink `
  -Path .claude/rules/csharp.md `
  -Target $HOME/.claude/rules-shared/csharp.md
```

需要管理員權限或啟用 Windows Developer Mode。

#### 方案 C:包成 plugin

把規則打包成 Claude Code plugin 散布(2026 Oct+ 機制)。

#### 方案 D:user-level 規則不用 paths

把 user-level 規則精簡到 ≤30 行,接受全 always-on 載入。

### 連結

https://github.com/anthropics/claude-code/issues/21858

## #16299 — 部分版本 paths rules 全載入(無視 frontmatter)

**Status**:Reported 2026 Jan 5
**確認平台**:macOS
**嚴重度**:🟡 中(影響 context bloat,非功能性錯誤)

### 症狀

某些 Claude Code 版本(< 2.0.64 之前)把 `.claude/rules/*.md` 全載入,**忽略 paths frontmatter**。結果:30 條 rule 全載入,context 爆炸。

### 驗證

```
/memory
```

對照 frontmatter:若 rule 有 `paths` 但仍顯示在 「always-loaded」清單,踩到此 bug。

### Workaround

#### 方案 A:升級

最新 Claude Code(2026 Mar+)已修正。

```bash
claude update
```

#### 方案 B:精簡 rules 內容

接受 always-on,但每條 rule ≤60 行,控制 always-on tokens。

### 連結

https://github.com/anthropics/claude-code/issues/16299

## #16853 — paths 規則在 Read 也偶有不載入

**Status**:Reported 2026 Jan 8
**確認平台**:macOS
**嚴重度**:🟡 中(邊緣案例)

### 症狀

Read 匹配 paths glob 的檔案,規則應該載入,但**偶爾不載入**。

```yaml
# .claude/rules/api/api-rules.md
---
paths: ["src/api/**"]
---
```

```
User: "Read src/api/routes.ts"
Claude: [reads file, but api-rules.md does NOT inject into context]
```

`/context` 命令也不顯示 api-rules.md 已載入。

### Workaround

#### 方案 A:`/memory` 主動驗證

每次依賴 paths 規則的工作前,先 `/memory` 確認規則真的載入。

#### 方案 B:重要規則移 CLAUDE.md

對任務成敗有關鍵影響的規則,放 CLAUDE.md 確保載入。

#### 方案 C:用 SessionStart hook 強制注入

```json
"SessionStart": [{
  "hooks": [{
    "type": "command",
    "command": "node .claude/hooks/inject-critical-rules.js"
  }]
}]
```

Hook 直接把規則內容用 `additionalContext` 注入。

### 連結

https://github.com/anthropics/claude-code/issues/16853

## 其他注意事項(非 GitHub issue 但實務有影響)

### A. Settings.json hooks 不會熱套用

**不是 bug,是刻意設計**(防惡意改寫)。修改 hooks 區塊後必須 `/clear` 或重啟 CLI。

### B. Subagent 不繼承 parent skills

**官方規範**:Subagent isolated context,必須 frontmatter `skills:` 顯式列出。

寫 subagent 時容易踩這坑(以為會繼承)。

### C. Shell profile 印字污染 hook JSON

`.bashrc` / PowerShell `$PROFILE.ps1` 印任何字到 stdout 會破壞 hook JSON parsing。

```bash
# 寫 hook 時用 --noprofile
bash --noprofile --norc -c "..."
```

### D. additionalContext 寫命令句被 surface 給使用者

Hook 注入的 context 寫成命令句(`DO NOT edit this`)會觸發 prompt-injection 防禦,被 surface 給使用者看,不會生效。

寫陳述句(`This file is generated by codegen.ts`)。

### E. 子目錄 CLAUDE.md 不會在 session start 載入

只有 cwd 與 ancestor 的 CLAUDE.md 在 session start 載入。子目錄的要 Claude **Read 該目錄檔案時**才 lazy-load。

### F. `--add-dir` 不會載入額外目錄的 CLAUDE.md

預設不載入。要設 `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` 才會。

但 `.claude/skills/` 在 added directory 內**會**自動載入(這是 skill 特例)。
