## 六要素(缺一即違反)

| # | 要素 | class | 規格 |
|:-:|------|-------|------|
| 1 | **NO 序號** | `mcard-no` | 卡片左上 mono 徽章 = **純數字流水號依序排開**(1, 2, 3…全局連續;使用者裁定 2026-06-06,非模組代號) |
| 2 | **名稱** | `mcard-name` | 模組名稱 + 代號後綴,格式「**{名稱} · {代號}**」(如「儀表板 KPI · M0-1」「DR 備份 / 還原後台 · G7」,代號移入名稱保留追溯),最多 2 行 line-clamp |
| 3 | **狀態標籤三組** | `mcard-tags` + `mtag mt-*` | 類型 × 校正階段 × 開發狀態,**可複選**(如「已規畫 + 暫緩施工」並存) |
| 4 | **用途說明** | `mcard-desc` | 自然語言白話(主要用途 + 任務內容),**≤5 行** line-clamp 固定 5 行高;詳情進報告頁 |
| 5 | **備註** | `mcard-note` > `mcard-note-clamp` | 注意事項白話,**≤3 行** line-clamp 固定 3 行高;無備註寫「—」保持等高 |
| 6 | **最後更新時間(日期+時間)** | `mcard-updated` | 卡片底部沉底(margin-top:auto);待規畫卡寫「—(報告待建)」 |

## 標籤三組色彩範式(色盲安全:顏色 + 幾何符號 + 文字三重編碼,禁只靠顏色)

### 第一組:類型(分類資訊 · 虛線低調樣式 `mt-type` + 色 class · **不註時間**)

| 類型 | 符號 | class | 色 |
|------|:---:|-------|-----|
| 地基 | ◆ | `mt-type-base` | brand 藍 |
| 功能層 | ▣ | `mt-type-func` | teal |
| 進階功能層 | ◈ | `mt-type-adv` | purple |
| 工具箱 / 工具層 | ⬢ | `mt-type-tool` | orange |

### 第三組:開發狀態

| 狀態 | 符號 | class | 色 |

## 時間註記規則

- **有事件時間的標籤必註時間**:`<i>YYYY-MM-DD</i>`(標籤內,豎線分隔樣式由 `.mtag i` CSS 自動處理)— 適用:校正完成 / 審查中 / 待審查(送審日)/ 已規畫 / 暫緩施工 / 開發中(開工日)/ 開發完成。
- **無事件的待態標籤不註**:待開發 / 待規畫(尚無時間可註)。
- 類型標籤不註(分類非狀態,無時間語意)。

## 等高鐵則

所有卡片高度嚴格一致 — 各區段固定高度:
- `mcard-head` min-height 48px(序號 + 名稱 2 行)
- `mcard-tags` min-height 52px(2 行標籤)
- `mcard-desc` 固定 5 行高(`calc(12.5px * 1.62 * 5)`)
- `mcard-note` 固定 3 行高(`calc(11.5px * 1.58 * 3 + 9px)`)
- `mcard-updated` 沉底(margin-top:auto)

**禁**內容超量撐破(超量必精簡至行數內,line-clamp 兜底裁切)。

## 其他規則

- **卡片排序按序號**:純數字流水號全局連續排序(分區內依模組代號邏輯序編號,如後台 28 卡 = M0 區 1-11 → 治理 G1-G10 為 12-21 → 軌道一 ①-⑥ 為 22-27 → P14 為 28;新增模組接續尾號)。
- **容器**:`<div class="mgrid">`(grid auto-fill minmax(330px,1fr));有報告連結用 `<a class="mcard" href>`;規劃中無連結用 `<div class="mcard mcard-static">`。
- **狀態變遷**(審查中→校正完成 / 待規畫→已規畫):只改標籤 class + 時間 + 更新時間,不破壞結構。
- 新模組卡一律依此範式建立。

## 模組報告內子功能項目狀態標註(2026-06-11 確立 · 使用者裁定)

> **雙層對應**:總覽卡片「開發狀態」三組標籤(✦/⚒/▢,§標籤三組第三組)標**模組層**整體狀態;模組報告(`module-{id}.html`)內**子功能項目**(★ 校正速覽六欄表格 row / 各章節卡片)逐項標**子功能層**狀態。目的:報告精確反映子功能粒度進度,讀者一眼知「哪些子功能做了+何時、哪些沒做+為什麼+何時做」。

### 子功能項目逐項標(速覽六欄表格 row / 章節卡片)

| 子功能狀態 | 標註 | 範例 |
|-----------|------|------|
| **已完成** | `✅ 已完成<i>日期時間</i>`(複用 `mt-dev-done` 語意或速覽表格 `b b-done`) | `✅ 已完成<i>2026-06-11 10:25</i>` |
| **未完成** | 備註**原因** + **後續完成階段**(禁只標「未完成」無下文) | `⏳ 未完成:字型多語系治理願景級 → 拆 m0-10b 漸進` / `⏳ 未完成:AIOS 擱置 → 隨解凍 defer` / `⏳ 未完成:6 admin 端點 → 歸 W2 8c` / `⏳ 未完成:user PDF 刪除端點 → 歸前台軌領域` |

### 鐵則:模組層 ↔ 子功能層一致性(防報告誤導)

模組總覽卡片標「✦ 開發完成」的**前提** = 報告內每個子功能項目皆「✅ 已完成」。若仍有 defer/未做子功能 → 模組卡應標「⚒ 開發中」(`mt-dev-doing`)**直到** defer 子功能完成,且報告內該子功能必標原因+後續階段。**禁**模組標「✦ 開發完成」但報告內含未完成子功能卻不註明原因+後續階段(模組看似全完成、實則有 defer 子功能 = 誤導)。
