# Anti-Patterns — 真實事故與避坑

這份是「踩過坑才知道」的清單。新增 hook 前對照一遍可省幾小時 debug。

---

## A1. shell profile 印歡迎訊息污染 JSON 輸出

**症狀**:Claude Code 在 verbose mode 顯示 `JSON parse error: Unexpected token 'W'`。

**原因**:你的 `.bashrc` / `$PROFILE.ps1` 有 `echo "Welcome, Alan!"` 或 oh-my-posh 之類的 prompt 印到 stdout。Hook script 經過 shell 啟動時,**這些字進到 stdout** → Claude Code 試圖 parse 失敗。

**修法**:
1. Hook 腳本內若呼叫 bash:`bash --noprofile --norc -c "..."`
2. 改用 `node`、`python` 之類直接執行,避開 shell
3. **不要**在 shell profile 裡放 stdout 輸出(無條件)

---

## A2. exit code 2 + JSON 輸出 → JSON 被忽略

**症狀**:你寫了 `{"hookSpecificOutput": {...}}` 然後 `exit 2`,結果 Claude 看不到 additionalContext。

**規範**:Claude Code 只在 **exit 0** 時解析 JSON。Exit 2 時只看 stderr。

**修法**:擇一,不可混用。
- Block: `console.error("reason"); process.exit(2);`
- Pass with context: `process.stdout.write(JSON.stringify({...})); process.exit(0);`

---

## A3. PreToolUse hook 阻擋了 SessionStart 想跑的命令

**症狀**:`claude --init` 跑 setup script 時被自己的 `git push` 守門 hook 擋下。

**原因**:Setup 階段內部可能跑 Bash,觸發 PreToolUse hooks。

**修法**:檢查 `data.hook_event_name` 與 `data.cwd` 後再決定是否啟用阻擋:
```javascript
if (data.permission_mode === 'plan') process.exit(0); // 計畫模式放行
```

---

## A4. Stop hook 永遠 exit 2 → 無限迴圈

**症狀**:Claude 跑完任務後反覆「我會繼續...」,session 燒 token 燒到爆。

**原因**:Stop hook 第二次以後被觸發時,`stop_hook_active === true`,但 hook 仍 exit 2 強制繼續。

**修法**(鐵則):
```javascript
if (data.stop_hook_active) process.exit(0);
```

---

## A5. timeout 設太短,Windows 下總被誤殺

**症狀**:Hook 在 macOS 同事的機器跑得好好的,你 Windows 上常 timeout。

**原因**:Windows 上 `cd "long-path-with-spaces"` + `node` cold start 至少 500-800ms。timeout 1000ms 的 hook 等於沒幾百毫秒可做事。

**修法**:
- 簡單 hook timeout 最少設 3000ms
- 重度 hook(讀檔、查 DB)設 5000-10000ms
- 用 `CLAUDE_PROJECT_DIR` 環境變數省去 `cd`

---

## A6. additionalContext 寫成命令句被 surface 給使用者

**症狀**:你寫 `"DO NOT edit this file"`,結果 Claude 直接把這句話顯示給使用者「Hook tells me not to edit...」。

**原因**:Claude Code 有 prompt-injection 防禦機制。當注入的文字看起來像「out-of-band command」,會 surface 給使用者讓他判斷。

**修法**:寫成**陳述句**(factual statement):
- ❌ `"DO NOT edit this generated file"`
- ✅ `"This file is generated by codegen.ts; source is in templates/"`

---

## A7. console.log 用來 debug 結果污染 JSON

**症狀**:Hook 跑起來明明邏輯沒問題,但 Claude Code 抱怨 `JSON parse failed`。

**原因**:你在 hook 中 `console.log("DEBUG: file=" + filePath)`,寫到 stdout,跟 JSON 混在一起。

**修法**:debug 訊息**只能**寫 stderr:
```javascript
console.error(`[DEBUG] file=${filePath}`); // ✅
console.log(`[DEBUG] file=${filePath}`);   // ❌ 污染 stdout
```

---

## A8. settings.json 改了但 hook 沒生效

**症狀**:你新增 hook,reload 視窗或重啟編輯器仍沒反應。

**原因**:Claude Code 在 **session 啟動時 snapshot** hooks,session 中途修改 settings.json **不會熱套用**。這是官方刻意設計,防止惡意改寫。

**修法**:
1. `/clear` 開新 session(會重讀 settings)
2. 或關 CLI 完全重啟

確認套用:`/hooks` 命令列出當前 session 已載入的 hooks。

## A9. path 用反斜線沒 escape

**症狀**:`SyntaxError: Unexpected token 'U' in JSON` 或路徑跑成 `C:UsersAlan...`。

**原因**:JSON 中 `\` 是 escape 字元。`"${USER_HOME}"` 變成 `C:UsersAlan`。

**修法**:擇一
- Escape: `"${USER_HOME}\\..."`
- 正斜線: `"${USER_HOME}/..."`(Windows 也接受)
- 環境變數: `"$CLAUDE_PROJECT_DIR/.claude/hooks/x.js"`(推薦)

---

## A10. http hook 公司網路阻擋

**症狀**:Hook 看起來呼叫了但都 timeout。

**原因**:公司 proxy / firewall 擋 outbound HTTP。或 `localhost:8080` server 沒啟動。

**修法**:
- 改 type: command 跑本地 script
- 或確認 service 健康(`curl http://localhost:8080/health`)
- 或在 hook script 內加 fallback timeout 後退到 silent pass

---

## A11. Subagent hook 沒繼承 parent 的 read 歷史

**症狀**:Phase 2 的 read-before-edit-guard hook 在 subagent 內誤判,subagent 明明該 edit 但被擋。

**原因**:Subagent 是 isolated context,有自己的 session_id,parent 的 read log 在另一個檔案。

**修法**:read log file 改以 git commit hash 或 worktree path 為 key,而非 session_id。

---

## A12. async hook 試圖 block

**症狀**:async hook 寫了 `exit 2` 但完全沒效果,使用者操作正常往下跑。

**原因**:async hook 在背景跑,Claude 已經拿到「pass」結果繼續工作了。exit 2 對它無效。

**修法**:async hook **只能**做 side-effect(log、上傳、寫檔)。需要 block 就不要用 async。

---

## A13. 多個同 matcher 的 hook 互踩

**症狀**:配置兩個 PreToolUse hook 都 matcher `Bash`,第一個改了 `updatedInput.command`,第二個沒看到改後版本。

**原因**:多個 hook **並行**(不是序列)執行,各自收到原始 `tool_input`。`updatedInput` 變更是合併後才生效。

**修法**:邏輯需要序列時,把多個檢查合併成單一 hook。

---

## A14. hook 把 secrets log 到 audit 檔

**症狀**:`.claude/audit/tools-*.jsonl` 內出現 API key、密碼。

**原因**:`tool_input.command` 可能含 `export API_KEY=...`,async-log hook 沒過濾就 append。

**修法**:log 前 sanitize:
```javascript
const safe = (data.tool_input?.command || '')
  .replace(/(api[_-]?key|password|token)\s*=\s*['"]?\S+/gi, '$1=***');
```

---

## A15. Hook 在 plan mode 太強硬

**症狀**:使用者用 `--plan-mode` 規劃時,hook 阻擋了所有 Edit/Write,使用者只能讀不能寫。

**原因**:Plan mode 下 Claude 仍會「假寫」做計畫評估,你的 PostToolUse hook 阻擋了。

**修法**:檢查 `data.permission_mode`:
```javascript
if (data.permission_mode === 'plan') process.exit(0);
```

---

## A16. PostToolUse hook 試圖回滾 → 沒用

**症狀**:PostToolUse hook 想 `exit 2` 撤回 Claude 剛做的 Edit,但檔案已經改了。

**原因**:PostToolUse 在工具**已執行完成**後才觸發。Exit 2 不會 undo。

**修法**:
- 想阻擋 → 用 PreToolUse(在執行前)
- PostToolUse 只能做後處理(加 lint、注入「請修正 X」提示)

---

## A17. Stop hook reason 太長被截斷

**症狀**:Stop hook 回 `{"decision": "block", "reason": "..."}`,Claude 行為怪異。

**原因**:`reason` 上限 10,000 字元,超過會被存檔並改傳檔案路徑,Claude 看到的是路徑不是內容。

**修法**:`reason` 寫摘要,細節寫 audit log 自己看。

---

## A18. Hook timeout 累加吃光時間預算

**症狀**:同一個事件掛 5 個 hook,timeout 各 3000ms,user 等 15 秒才見到回應。

**原因**:雖然 hook 並行,但 Claude Code 會等所有 hook 完成。最慢的決定總等待時間,timeout 是上限。

**修法**:
- 重度 hook 改 `async: true`
- 整併同類 hook
- 砍掉不重要的觀測 hook

---

## A19. Path-based rules 在 Write 時不載入(Bug)

**症狀**:`.claude/rules/foo.md` 有 `paths: "**/*.cs"` frontmatter,Claude 建立新 .cs 檔時 rule 沒生效。

**原因**:[Issue #23478](https://github.com/anthropics/claude-code/issues/23478) — paths rules 只在 **Read** 觸發,Write/Create 不觸發。

**修法**:
1. **重要規則同時放 CLAUDE.md**(犧牲 paths 的細粒度)
2. 用 **PostToolUse hook** 偵測 Write 並注入規則 context(本 skill 的 Template B 就是這設計)

---

## A20. User-level rules 的 paths frontmatter 完全失效(Bug)

**症狀**:`~/.claude/rules/csharp.md` 加了 `paths: "**/*.cs"` 但永遠不載入。

**原因**:[Issue #21858](https://github.com/anthropics/claude-code/issues/21858) — user-level rules 不支援 paths 過濾。

**修法**:
- 把這類規則放專案層 `.claude/rules/`(可以多專案 symlink 同一份)
- 或不用 paths,改 hook 路線

---

## 補充事故來源(社群 + 官方)

- Cursor / Copilot hooks 用 `command` 而非 `if` 條件 → Claude Code 兩者都支援。`if: "Bash(rm *)"` 是 Claude Code 獨有,可用 permission rule syntax 在 hook 層做初篩
- Plugin hooks **不能**包含 `hooks`、`mcpServers`、`permissionMode` 三欄位(安全考量)
- `disableAllHooks: true` 一次關所有 hooks(緊急逃生用)
- `allowManagedHooksOnly: true` 只跑管理層部署的 hooks(企業環境)
