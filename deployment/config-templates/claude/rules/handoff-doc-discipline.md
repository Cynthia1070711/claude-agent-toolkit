# Handoff Doc Discipline — 跨 session 交接文檔精簡規範

> **建立**: 2026-06-03 · CC-OPUS · **觸發**: 前台軌任務交接文檔累積至 293 行臃腫（已完成模組記錄/歷史/TZ 明細塞滿主檔）。
> **嚴重等級**: HIGH · paths-scoped（交接文檔路徑 lazy-load）

## Core Principle

跨 session 交接**主檔**是「**給接手者看的當前狀態索引 + 下一步指引**」,**不是歷史日誌**。已完成項目詳述 / 歷史脈絡 / Phase D 明細一律拆子目錄歸檔,主檔只記狀態。**行數上限 ≤ 120**。

## 6 章節範本（≤ 120 行）

| # | 章節 | 內容 |
|:-:|:-----|:-----|
| 1 | 文檔規範 | 本檔精簡規範說明 + 指向本 rule |
| 2 | 建檔資訊 | 建檔者 / 建檔時間 / 更新時間 / 更新者 / **當前任務** / **下一個任務** |
| 3 | 總項目圖 | 各功能模組狀態（✅完成 / 🔄進行中 / ⬜待）,已完成**只記狀態不詳述** |
| 4 | 注意事項 | 紀律 CRITICAL + 5 步驟循環指標 + **下一個項目啟動提示** |
| 5 | 備註 | Phase D 待辦指標 + 歷史歸檔指向 + Memory 脈絡 |
| 6 | 其他引用 | 任務紀律 / 清單 / 報告 / 溝通管道 / 歷史歸檔 / rule |

## 歷史歸檔（子目錄）

主檔同層建 `{軌}交接歷史/` 子目錄,放:
- `01-模組完成記錄歸檔.md` — 已完成項目詳述（真相錨點 / 教訓 / Story 接合）
- `02-PhaseD待辦與脈絡歸檔.md` — Phase D 待辦明細 + 任務全貌 + 教訓 + 跨軌協作

## 更新流程（每完成一項目）

1. §建檔資訊:更新「更新時間 / 更新者 + 當前任務 + 下一個任務」
2. §總項目圖:該項目改 ✅ + 下一個改 🔄
3. §注意事項:更新「下一個項目啟動提示」
4. **完成詳述寫入歷史檔 01**（非主檔）→ 主檔不增行
5. 每次更新 diff 控制小範圍,主檔行數不漲

## FORBIDDEN

### F1 — 主檔累積已完成項目詳述
- **Forbidden**: 每完成一項目在主檔加完成記錄段（真相錨點 / finding / Story 接合詳述）
- **Common Rationalization**: 「完成記錄放主檔方便接手者看」/「歷史脈絡有價值不想拆」
- **Red Flag**: 主檔出現 ≥ 3 個「{項目} 完成記錄」詳述段;主檔行數 > 120

### F2 — 歷史 / 明細塞主檔不拆子目錄
- **Forbidden**: TZ 待辦明細表 / 教訓清單 / 任務全貌歷史 累積主檔
- **Common Rationalization**: 「都相關放一起比較完整」
- **Red Flag**: 主檔含完整明細表（> 10 行）而非指標 + 歸檔指向

### F3 — 拆分未確認就刪（資訊遺失）
- **Forbidden**: 歷史內容未確認搬到歸檔檔就從主檔刪
- **Common Rationalization**: 「應該都搬過去了」
- **Red Flag**: transcript 缺「歸檔檔已含該內容」確認;直接刪主檔段落（對齊 `report-paradigm` skill §5 安全整合刪除流程〔原 doc-consolidation rule,2026-06-06 遷移〕）

## Self-Check（更新交接主檔前 4 題）

1. 我要加的是「狀態變更」還是「完成記錄詳述」? 詳述 → 寫歷史檔 01,主檔只改狀態
2. 主檔行數是否 ≤ 120? 超過 → 拆歷史
3. 已完成項目我是否只在 §總項目圖記狀態（非詳述）?
4. 拆分刪除前,內容是否已確認在歷史歸檔檔?

任一 No → **STOP**。
