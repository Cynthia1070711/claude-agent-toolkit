### 4.1 41 條 Rules 分類逐項

Rules 放在 `.claude/rules/*.md`，由 frontmatter `paths:` 條件載入（僅少數 always-on），
避免無關規範佔用 context。

#### SUPREME 憲政層（4，最高優先）

| Rule | 管什麼 |
|------|--------|
| `constitutional-standard` | **Code Verification**（結論必 Read 實際 code 取 file:line，禁只憑文檔）+ **Timestamp**（必 offset-aware，禁 naive 時間）+ **Language**（使用者可見輸出一律繁中） |
| `constitutional-backend-contract` | DB schema / API contract / Entity 語意必引 backend code file:line |
| `constitutional-depth-first` | 檢查/驗證類任務必走深度路徑 + 4 條 Audit 反模式 |
| `constitutional-external-citation` | 引用外部文檔必走 DETECT→FETCH→CITE 三步 + 30 詞投機表禁用 |

#### 架構治理（7）

| Rule | 管什麼 |
|------|--------|
| `capability-integration-mandate` | 新增 MCP tool / DB schema / RAG Layer 必走 5 步整合（SKILL 同步 → BMAD 整合 → Hook 注入 → 部屬範本 → migration + 公告），防「能力建好沒人用」 |
| `cross-ref-discipline` | 動 `.claude/**` 前必先 GitNexus + Grep 跨檔查引用，防僵屍檔 / 殘留 ref / 參照遺失 |
| `single-engine-mode` | `.claude/` 為唯一 SSoT，`.agent/` `.gemini/` 凍結保留不同步 |
| `skill-creation-discipline` | Skill 規模治理與退役 |
| `skill-sync-gate` | Skill ↔ Code 同步閘門 |
| `skill-idd-sync-gate` | IDD `forbidden_changes` 保護 |
| `skill-tool-invocation-mandatory` | 改 SKILL.md 前必字面呼叫 `Skill(skill="saas-to-skill")` |

### 4.3 ★ 違規學習閉環

這是「不讓 AI 重踩同一個坑」的機制：

```
   AI 違反某條 rule
        │
        ▼
   Stop: detect-rule-violation-hint.js 偵測
        │  （比對 .claude/rules/ 與本次操作）
        ▼
   INSERT context_entries（category=rule_violation，JSON 格式）
        │
        ├──▶ DevConsole /rule-violations 人工檢視
        │
        ▼
   下次 prompt: pre-prompt-rag.js Layer 11
        │  查最近 30 天違規，依頻次排序
        ▼
   注入「⚠️ 最近 30 天違規熱區」到 AI 的 context
        │
        ▼
   AI 開工前就看到「你最近在 X 上犯過 4 次錯」
        │
        ▼
   PreToolUse: rule-violation-write-guard.js 二次攔截
```

**輔助工具**：`check-violation-recurrence.cjs`（複發檢查）· `backtest-rule-violation-detector.cjs`
（偵測器回測）· `query-violations.js` · `log-rule-violation.js`
