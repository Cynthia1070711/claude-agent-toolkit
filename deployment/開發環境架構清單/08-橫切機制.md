# §7.5 橫切機制（不屬單一子系統，但整個環境都在用）

**版本**: 3.0.0
**建立日期**: 2026-08-07 15:56:13
**更新日期**: 2026-08-07 20:33:33
**上層**: [開發環境架構清單（總表）](../00-開發環境架構清單.md)

> 不屬單一子系統的 8 項設施 —— OTel / Token 預算 / 狀態列 / 檔案鎖 / Worktree / 規則稽核 / 事件匯流排 / 外部方案閘門

---

以下 8 項機制跨越多個子系統，容易在「按子系統分類」時被遺漏。

### 1. 可觀測性（OpenTelemetry 微型收集器）

| 項目 | 內容 |
|------|------|
| 收集器 | `scripts/otel-micro-collector.js` — 本機輕量 OTel collector |
| **實測 Port** | **49152**（⚠ `.claude/rules/context-memory.md` 記載的 49200 為舊值，以程式碼為準） |
| 啟動 | `scripts/otel-auto-start.js`（SessionStart hook，冪等） |
| 彙總 | `scripts/otel-session-aggregate.js`（SessionEnd hook，glob-resilient） |
| 主視窗啟動 | `scripts/start-main-otel.ps1` |
| Skill | `phycool-otel-micro-collector`（含 rotation 設計） |
| 用途 | 追蹤各 workflow 的 token 消耗、耗時、失敗率，寫入 `workflow_executions`（1,050 筆） |

### 2. Token 與 Context 預算管理

| 元件 | 職能 |
|------|------|
| `.context-db/scripts/context-budget-monitor.js` | 累計 `conversation_turns.token_estimate`，監控 context 用量 |
| `.claude/hooks/suggest-compact.js`（Stop） | 用量偏高時建議壓縮 |
| `.claude/hooks/precompact-tool-preprune.js`（PreCompact） | 壓縮前裁剪工具定義，保留對話內容 |
| `scripts/pipeline-quota-check.js` | Pipeline 派發前檢查配額，防中途耗盡 |
| `scripts/token-cache-health-advisor.cjs` | prompt cache 健康度建議 |
| `scripts/pipeline-log-tokens.js` | 逐階段 token 記錄 |
| `.context-db/scripts/inject-budget.cjs` | 各 RAG Layer 的字元預算分配（見 §3.2） |
| Skill | `claude-token-decrease` — 減量策略方法論 |

### 3. 狀態列（StatusLine）

`settings.json` → `statusLine: node scripts/pipeline-statusline.cjs`
即時顯示當前 Pipeline 狀態、軌別、進行中的 Story。
全域另有 `~/.claude/statusline.js` 與 `statusline-command.sh`（被專案設定覆蓋）。

### 4. 檔案鎖並行控制

多個 Claude Code 視窗同時工作時，防止兩邊改同一個檔。

| 元件 | 掛載點 |
|------|--------|
| `scripts/file-lock-check.ps1` | **PreToolUse**（Edit\|Write）— 檢查是否被他人鎖定 |
| `scripts/file-lock-acquire.ps1` | **PostToolUse**（Edit\|Write）— 登記鎖 |
| `scripts/file-lock-release.ps1` | 手動／收尾釋放 |
| `.agent-locks.json` | 鎖狀態檔（專案根） |

鎖以 `-AgentId`（如 `CC-OPUS`）識別持有者，對應 `CLAUDE.local.md` 的引擎身分矩陣。

### 5. Worktree 並行隔離

| 項目 | 內容 |
|------|------|
| 位置 | `.claude/worktrees/`（`.gitignore` L81 排除） |
| Skill | `worktree-manager` |
| Pipeline 整合 | `dispatch-general.ps1 -Worktree` — 子視窗在獨立 git worktree 執行，避免並行改檔衝突 |
| 成本 | 每個 worktree 約 200-500ms 建立 + 磁碟空間；未變更時自動移除 |
| 速查 | `worktree-quick-reference.md` |

### 6. 規則載入稽核

`.claude/hooks/instructions-loaded-logger.js`（**InstructionsLoaded** 事件）
→ `.claude/audit/instructions-loaded.log`（實測 511 KB）

**為什麼需要**：41 條 rules 多數為 `paths:` 條件載入，但 Claude Code **Bug #23478** 使
paths-scoped 規則在 Write 工具觸發時不載入。此 log 記錄每次實際載入了哪些規則，
用於驗證 `paths:` 設定是否如預期生效。變更 rule 的 `paths:` 後應對照此 log 複核。

### 7. AIOS 事件匯流排

| 元件 | 職能 |
|------|------|
| `.claude/hooks/event-bus-publisher.js`（PostToolUse） | 發布工具事件 |
| `.claude/hooks/_aios-sql.js` | 共用 SQL 模組 |
| Skills | `aios-orchestrator` · `aios-event-bus` · `aios-scheduler` · `aios-resource-coord` |
| 狀態 | 專案層面已擱置（賦能計畫優先），機制保留 |

### 8. 外部方案評估閘門（Tianji Pavilion）

引入任何外部工具／方案前的自我約束機制，防「看到新玩具就想裝」。

| Hook | 攔截時機 |
|------|---------|
| `tianji-q4-audit-gate.js`（PreToolUse） | 強制先盤點自家已有能力 |
| `tianji-baseline-snapshot-gate.js`（PreToolUse） | 試點前必先留基準快照 |
| `tianji-impulse-cooldown-guard.js`（PreToolUse） | 衝動引入冷卻 |
| `tianji-concurrent-pilot-guard.js`（PreToolUse） | 防同時開多個試點 |
| `tianji-reject-cooldown-check.js`（UserPromptSubmit） | 已否決方案的冷卻期 |
| `tianji-pilot-timebox-monitor.js`（SessionStart） | 試點時間盒監控 |
| `tianji-scope-creep-detector.js`（PostToolUse） | 範圍蔓延偵測 |
| `tianji-ssot-sync-checker.js`（PostToolUse） | SSoT 同步檢查 |

資料表：`baseline_snapshots` · `external_evaluations`。Skill：`tianji-pavilion`。

> **設計緣起**：此機制本身即為 dogfood 產物 —— 首次應用時就發現「自家 graph capability
> 已 70% ready 但 BMAD workflow 零調用」，據此建立了 `capability-integration-mandate.md`
> （見 §4.1 架構治理）。
