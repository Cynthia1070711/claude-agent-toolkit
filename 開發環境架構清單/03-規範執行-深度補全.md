> 它們靠 paths 觸發，正是 §4.1.2 的 Bug #23478 兜底機制存在的原因。

## 4.3 ★ 違規學習閉環（完整閉環圖 + 實測驗證）

### 4.3.1 閉環流程（含 Hook 掛載點與 DB 表）

```
AI 違反某條 rule
    │
    ▼
Stop: detect-rule-violation-hint.js 偵測
    │  （比對 .claude/rules/ 與本次操作的工具調用）
    ▼
INSERT context_entries（category=rule_violation，JSON 格式）
    │  content: {violated_rule_path, workflow_phase, timestamp, details}
    ▼
    ├──▶ DevConsole /rule-violations 人工檢視
    │
    ▼
下次 prompt: pre-prompt-rag.js Layer 11
    │  查最近 30 天違規，依頻次排序 (getRecentHotViolations)
    ▼
注入「⚠️ 最近 30 天違規熱區」到 AI 的 context
    │  格式: - ❌ **ruleName** (phase) × freq — 最後違規: X 天前 🔴 本 session N 次
    ▼
AI 開工前就看到「你最近在 X 上犯過 4 次錯」
    │
    ▼
PreToolUse: rule-violation-write-guard.js 二次攔截
    │  讀取 Layer 11 注入的熱區，匹配即將觸發的工具
    ▼
若匹配 → BLOCK 並回饋原因
```

## 4.4 Rules/Hooks 開發與維護紀律

### 4.4.1 新增 Rule 流程

1. 建立 `.claude/rules/{rule-name}.md`，含 frontmatter `paths:` (或 `always: true`)
2. 執行 `Skill(skill="skill-builder")` Mode A 驗證
3. 同步 `skills_list.md` 索引
4. 驗證 `instructions-loaded-logger.js` 記錄載入正常

### 4.4.2 新增 Hook 流程

1. 建立 `.claude/hooks/{hook-name}.js`，遵循 `hooks-creation-discipline.md`
2. 於 `settings.json` 註冊掛載點（event + matcher）
3. 編寫 `.test.js` 單元測試 (放同目錄)
4. 註冊 `_lib.js` 共用模組若需
